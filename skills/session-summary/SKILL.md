# Session Summary

現在のセッションの会話内容を分析し、日本語の要約Markdownファイルを生成する。

## ワークフロー

### 1. 要約スタイルを選択してもらう

スキル実行時、最初に AskUserQuestion ツールを使って要約のスタイルをユーザーに選択してもらう。

選択肢:
1. **構造化テンプレート** — 時系列の議論の流れ、決定事項、学び、次のステップなど、セクションごとに整理された詳細な要約
2. **要点まとめ** — 形式にこだわらず、セッションで最も重要だったことを簡潔にまとめる。本質的な内容にフォーカス
3. **カスタム指定** — ユーザーが自由に要約の形式や観点を指定する

「カスタム指定」が選ばれた場合は、続けてどのような形式・観点で要約してほしいかをユーザーに聞く。

### 2. 会話を分析する

現在のセッション全体を振り返り、選択されたスタイルに応じて情報を抽出する:

- 議論されたトピック
- 各トピックの背景・内容・結果
- 明示的な決定事項とその理由
- 作成・変更されたファイル
- 技術的な発見や学び
- 未完了のタスクや次のステップ

### 3. 要約を生成する

選択されたスタイルに応じて要約を作成する:

- **構造化テンプレート**: [summary-template.md](references/summary-template.md) のフォーマットに従う
- **要点まとめ**: テンプレートに縛られず、セッションの核心を自然な文章でまとめる。重要な決定・発見・成果物を中心に、読み返したときに「このセッションで何が起きたか」がすぐ分かる形にする
- **カスタム指定**: ユーザーの指示に従う

共通ルール:
- 言語は常に日本語
- 簡潔に、しかし重要な文脈は省略しない
- 決定事項には「なぜ」を併記する
- コード変更がないセッションでは「作成・変更したファイル」セクションを省略する
- セッション中に表・テーブル・比較表などが提示された場合、要約にもマークダウンのテーブル形式で再現する（テキストで説明するより視覚的にわかりやすいため）

### 4. レビューとフィードバック

要約を生成したら、まずチャット上にマークダウンとしてそのまま表示する（まだファイルには保存しない）。

表示後、AskUserQuestion で確認する:
- **このまま保存** — 内容に問題なし、ファイルとして保存する
- **修正してほしい** — フィードバックを入力して修正版を再生成する
- **キャンセル** — 要約の作成を中止する

「修正してほしい」が選ばれた場合は、ユーザーのフィードバック内容に基づいて要約を修正し、再度チャット上に表示→確認を繰り返す。ユーザーが「このまま保存」を選ぶまでこのループを続ける。

「キャンセル」が選ばれた場合は、ファイルを保存せずにスキルを終了する。

### 5. ファイルとして保存し、開く

- ファイル名: `session-summary-YYYY-MM-DD-{短い説明}.md`
- 保存先: 現在の作業ディレクトリ
- 例: `session-summary-2026-02-18-generative-art.md`

保存後:
1. ファイルパスをユーザーに伝える
2. Bash ツールで `open {ファイルパス}` を実行し、デフォルトのエディタ/ビューアでファイルを自動的に開く
