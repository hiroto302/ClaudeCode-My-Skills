# 目的別分析プロンプトテンプレート

このファイルは `/video_ref` スキルの Step 6 で使用する、目的カテゴリ別の分析プロンプトを定義する。

---

## 共通プリアンブル（全カテゴリ共通）

```
あなたは動画のフレームを連続的に分析して、ユーザーの目的に合った情報を抽出する専門家です。
ユーザーは「{intent_label}」の目的でこの動画を分析しています。

以下のフレーム画像を見て、目的に必要な情報を具体的に抽出してください。
前のフレームからの**変化**に特に注目してください。
```

---

## ui_reproduction: UIの再現・実装

```
このフレームについて以下を分析してください:

1. **レイアウト構造**
   - 全体のレイアウトパターン（シングルカラム/2カラム/グリッド等）
   - 主要な領域の配分（ヘッダー、サイドバー、メインコンテンツ、フッター）
   - 推定グリッド数、ガター幅

2. **UIコンポーネント**
   - 画面上の主要コンポーネント（ボタン、カード、フォーム、ナビゲーション等）
   - 各コンポーネントの状態（active, hover, disabled 等）
   - アイコン、画像、テキストの配置

3. **ビジュアルデザイン**
   - 背景色・テキスト色の推定値（HEX形式）
   - フォントサイズの推定（px）
   - 余白・パディングの推定（px）
   - ボーダー、シャドウ、角丸の有無と推定値

4. **前フレームからの変化**
   - レイアウトの変更点
   - 新しく出現/消失した要素
   - 状態が変化した要素

5. **実装に必要な技術**
   - 推奨 CSS 手法（Grid/Flexbox/Position 等）
   - 推奨コンポーネントライブラリ（shadcn/ui, MUI 等）
```

## animation: アニメーション・トランジション

```
このフレームについて以下を分析してください:

1. **アニメーション対象の特定**
   - 動いている/変化している要素は何か
   - 要素の現在の状態（位置、サイズ、透明度、色、形状）

2. **前フレームからの変化量**
   - 位置の移動量（推定px、方向）
   - サイズ変化（推定比率）
   - 透明度変化（推定値 0.0-1.0）
   - 色の変化（推定HEX値）
   - 回転・変形の有無と推定角度

3. **遷移の詳細**
   - 遷移の種類（フェード/スライド/ズーム/モーフィング/回転等）
   - 推定 duration（ms）
   - 推定 easing 関数（linear, ease-in, ease-out, ease-in-out, cubic-bezier）
   - 遷移の方向（左→右、上→下、中心→外側等）

4. **トリガーの推定**
   - 何がこのアニメーションを開始したか（hover, click, scroll, load, timer）
   - 連鎖的なアニメーションの有無（stagger, sequence）

5. **実装に必要な CSS/JS プロパティ**
   - transform（translate, scale, rotate）の具体的な値
   - opacity, clip-path, filter 等の値
   - animation-timing-function の推定
   - 推奨実装方法: CSS Keyframes / CSS Transition / Framer Motion / GSAP
```

## error_fix: エラー・バグの修正

```
このフレームについて以下を分析してください:

1. **画面の状態**
   - 現在表示されている画面の名前/役割
   - 画面上のUI要素の状態
   - 正常と思われる部分

2. **異常・エラーの検出**
   - エラーメッセージの有無（テキストを正確に読み取る）
   - コンソールエラーの表示（DevTools が開いている場合）
   - レイアウトの崩れ、要素の重なり、表示切れ
   - 予期しない空白、ローディングの停滞
   - 色やスタイルの異常

3. **前フレームからの変化**
   - エラーが発生した瞬間の特定
   - エラー発生前の正常な状態との差分
   - ユーザーが何を操作した直後にエラーが起きたか

4. **推定される原因**
   - フロントエンドのエラーか（JS, CSS, HTML）
   - バックエンドのエラーか（API, DB）
   - ネットワークエラーか
   - 状態管理の問題か

5. **修正のための情報**
   - 再現手順の推定
   - 影響範囲の推定
   - 修正方針の提案
```

## ui_flow: UIフロー・操作手順

```
このフレームについて以下を分析してください:

1. **画面の識別**
   - この画面の名前/役割の推定（ログイン、ダッシュボード、設定等）
   - URL パスの推定（/login, /dashboard, /settings 等）
   - ページタイトルやブレッドクラムの読み取り

2. **画面の構成要素**
   - 主要なUI要素とその役割
   - インタラクティブ要素（ボタン、リンク、フォーム）
   - 表示されているデータの種類

3. **前フレームからの遷移**
   - どの要素をクリック/操作して遷移したか
   - 遷移の種類（ページ遷移、モーダル表示、タブ切替、アコーディオン開閉等）
   - 遷移時のアニメーション（あれば）

4. **ユーザーアクション**
   - この画面でユーザーが行った/行うであろう操作
   - フォーム入力、ボタンクリック、スクロール等

5. **実装のための情報**
   - ルーティング構造の推定（React Router, Next.js App Router 等）
   - 状態管理の必要性（ログイン状態、フォームデータ等）
   - API コールの推定（どの画面でデータ取得が必要か）
   - 共通コンポーネント（ヘッダー、ナビ、フッター）の特定
```

## custom: カスタム目的（Other 選択時）

```
このフレームについて以下を分析してください:

ユーザーの目的: {user_custom_intent}

1. **画面の内容**
   - 表示されている要素の詳細な説明
   - テキストの読み取り

2. **前フレームからの変化**
   - 何がどのように変化したか
   - 変化の程度と種類

3. **ユーザーの目的に関連する情報**
   - 上記の目的に照らして、このフレームから読み取れる重要な情報
   - 実装/修正/改善のために必要な具体的な詳細

4. **実装への示唆**
   - この内容を実現/修正するために必要な技術的アプローチ
```
