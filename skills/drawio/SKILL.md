# Draw.io Diagram Generator

Draw.io MCP ツールを使い、3ステップのインタラクティブなワークフローでプロジェクトの図表を生成する。

## ワークフロー

### Step 1: 設定を一括選択してもらう

AskUserQuestion ツールで **4つの質問を1回のウィンドウで同時に** 表示し、すべての設定を一括で選択してもらう。

**質問1: 出力形式**（header: "形式"）
選択肢:
1. **XML（推奨）** — 座標・色・スタイルを完全制御。アーキテクチャ図やデータフロー図に最適
2. **Mermaid** — 自動レイアウト。シーケンス図やER図に最適。記述が簡潔
3. **CSV** — データ駆動の自動生成。組織図やツリー構造に最適

**質問2: 図の種類**（header: "種類"）
選択肢:
1. **アーキテクチャ図** — プロジェクト構成、モジュール依存関係、技術スタック
2. **シーケンス図** — モジュール間の通信フロー、非同期処理、APIコール順序
3. **状態遷移図** — UI状態、アプリケーション状態のライフサイクル
4. **データフロー図** — データの変換過程、パイプライン、入出力の流れ

「Other」が選ばれた場合、以下のような図の種類にも対応する:
- ユーザーフロー図、デプロイ/インフラ構成図、ER図、クラス図、フローチャート

**質問3: 詳細度**（header: "詳細度"）
選択肢:
1. **詳細（推奨）** — 各モジュールの内部構造（関数・イベント・データ構造）まで掘り下げて描く。キャンバスを広く使い、情報量を最大化する
2. **簡潔** — モジュール単位の概要にとどめ、内部の関数やイベントは省略する。全体の構造をひと目で把握するのに最適

**質問4: 対象の指定方法**（header: "対象"）
選択肢:
1. **自動解析（推奨）** — 現在のプロジェクトのコードを読み取り、自動で図の内容を構成する
2. **手動で指定** — ユーザーが図に含めたい要素や範囲を自由に記述する

「自動解析」が選ばれた場合:
- Glob/Grep/Read ツールを使い、プロジェクトのソースコードを分析する
- CLAUDE.md があればアーキテクチャ情報を参照する
- 分析結果に基づき、図に含めるべき要素を自動で決定する

「手動で指定」が選ばれた場合:
- ユーザーの入力内容に従って図を構成する

### Step 2: 図を生成する

選択された形式に応じて、対応する MCP ツールで図を生成する:

- **XML** → `mcp__drawio__open_drawio_xml` を使用
- **Mermaid** → `mcp__drawio__open_drawio_mermaid` を使用
- **CSV** → `mcp__drawio__open_drawio_csv` を使用

共通パラメータ: `dark: "true"`（ダークモード固定）

### Step 3: フィードバックと修正

図を生成した後、AskUserQuestion で確認する:
- **OK、完了** — 図に問題なし、Step 4 へ進む
- **修正してほしい** — フィードバックを入力して図を再生成する

「修正してほしい」が選ばれた場合は、フィードバック内容を反映して再生成し、再度確認を繰り返す。

### Step 4: ファイルを自動保存する

「OK、完了」が選ばれたら、生成した図のソースコンテンツをファイルとして現在の作業ディレクトリに保存する。

**ファイル形式:**
- XML → `.drawio` ファイル（draw.io ネイティブ形式、そのまま開ける）
- Mermaid → `.mmd` ファイル
- CSV → `.csv` ファイル

**ファイル名の命名規則:**
`{図の種類}-{内容の要約}.{拡張子}`

- 図の種類: `architecture`, `sequence`, `state`, `dataflow`, `er`, `flowchart` など
- 内容の要約: 図の主要な対象を英語のケバブケースで 2〜4 語（例: `bg-removal-pipeline`, `worker-message-flow`）

例:
- `architecture-bg-removal-web.drawio`
- `sequence-worker-message-flow.mmd`
- `state-app-lifecycle.csv`

**保存手順:**
1. Write ツールで現在の作業ディレクトリにファイルを保存する
2. 保存したファイルパスをユーザーに伝える

## 注意事項

- 図の言語は日本語をベースとし、技術用語・関数名・ファイル名は英語のまま使用する
- **詳細度の選択に従う**:
  - 「詳細」: 各モジュールの内部構造（関数・イベント・データ構造）まで掘り下げて描く。コードを読んで得られた情報は積極的に図に反映する。コンテナ（グループ枠）を活用して階層的に整理する。キャンバスサイズを広げて情報量を確保する
  - 「簡潔」: モジュール単位のボックスと接続関係のみ描く。内部の関数・イベントは省略し、各ボックスには役割の1行説明だけ記載する。コンパクトなキャンバスで全体像を俯瞰しやすくする
- ラベルは短く、読みやすさを最優先する
- 色は5〜6色を使い分け、凡例（Legend）を必ず含める
