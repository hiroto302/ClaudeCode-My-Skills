# SoundConverter

`.m4a` 音声ファイルを ffmpeg で `.mp3`（192kbps CBR）に変換するスキル。
ファイル単体・ディレクトリ（トップ階層）のいずれにも対応し、出力は **入力と同じディレクトリ** に同名で書き出す。

## Trigger

ユーザーが `/sound-converter` と入力した時、または「m4aをmp3に変換して」「音声を変換」と言った時にこのスキルを実行する。

## 進捗表示ルール

各ステップで以下のヘッダー形式を **必ず** 出力する:

**ヘッダー形式:** `### Step {番号}: {ステップ名}`

| Step | ヘッダー | 表示内容 |
|------|---------|---------|
| 0 | `### Step 0: 前提チェック` | ffmpeg の有無 |
| 1 | `### Step 1: 入力の解決` | 入力パスと種別（ファイル/ディレクトリ） |
| 2 | `### Step 2: 対象一覧` | 変換対象の .m4a 一覧テーブル |
| 3 | `### Step 3: 変換実行` | 各ファイルの変換結果（成功/スキップ/失敗） |
| 4 | `### Step 4: 結果サマリー` | 全体の集計テーブル |

ステップを省略したり、ヘッダーなしで実行したりしないこと。

## Workflow

### Step 0: 前提チェック

`which ffmpeg` を実行して導入を確認する。見つからない場合は以下を表示して **終了** する:

> FFmpeg がインストールされていません。以下のコマンドでインストールしてください:
> ```bash
> brew install ffmpeg
> ```

### Step 1: 入力の解決

1. `$ARGUMENTS` が指定されていればそれを入力パスとする
2. 未指定なら `AskUserQuestion` で入力パス（ファイル または ディレクトリ）を尋ねる
3. `stat` でパスの種別を判定:
   - **存在しない**: エラーを表示して終了
   - **ファイル**: 拡張子が `.m4a` か（大文字小文字を無視して）検証。`.m4a` でなければ「対応していない形式です」と表示して終了
   - **ディレクトリ**: Step 2 で `Glob` を使って `*.m4a` を列挙する（再帰しない）

入力情報をテーブルで表示:

| 項目 | 値 |
|------|-----|
| 入力パス | {path} |
| 種別 | ファイル / ディレクトリ |

### Step 2: 対象一覧

- 入力がディレクトリの場合、`Glob` パターン `{dir}/*.m4a` で対象を列挙する（サブディレクトリは含めない）
- 入力がファイルの場合、その 1 件のみが対象

対象ファイルを Markdown テーブルで表示:

| # | ファイル | サイズ |
|---|---------|--------|
| 1 | {filename} | {size} KB |

末尾に件数を表示する（例: `対象: 3 件`）。

**対象が 0 件の場合**: 「変換対象の .m4a が見つかりませんでした」と表示して終了する。

### Step 3: 変換実行

各 `.m4a` ファイルについて以下を順に実行する。

#### 3-1. 出力パス決定

出力パスは入力と同じディレクトリ、同じベース名で拡張子を `.mp3` にする:
- 入力 `/path/to/sample.m4a` → 出力 `/path/to/sample.mp3`

#### 3-2. 既存ファイルチェック

出力 `.mp3` が既に存在する場合は **AskUserQuestion** で挙動を確認する:

- **上書き**: そのファイルだけ上書きする
- **スキップ**: そのファイルは変換しない
- **残り全て上書き**: このファイル以降の既存出力は全て上書き（質問しない）
- **残り全て スキップ**: このファイル以降の既存出力は全てスキップ（質問しない）

`残り全て*` を選んだ場合、以降のループでは AskUserQuestion を出さずにその選択を適用する。

#### 3-3. ffmpeg 実行

```bash
ffmpeg -hide_banner -loglevel error -y \
  -i "{input.m4a}" \
  -codec:a libmp3lame -b:a 192k \
  -map_metadata 0 \
  "{output.mp3}"
```

- `-y` は既存ファイル上書き許可。スキップ判定済みのファイルはここまで来ないので常に `-y` で問題ない
- timeout は 60000ms（1分）で十分。長尺の場合は延長

#### 3-4. 結果記録

ffmpeg の終了ステータスと出力ファイルのサイズを記録する（成功/失敗）。
スキップしたファイルも記録する。

### Step 4: 結果サマリー

結果を Markdown テーブルで表示:

| ファイル | 状態 | 入力サイズ | 出力サイズ | 出力パス |
|---------|------|-----------|-----------|---------|
| {file1} | 成功 | {kb} KB | {kb} KB | {path} |
| {file2} | スキップ | {kb} KB | — | — |
| {file3} | 失敗 | {kb} KB | — | {error_msg} |

末尾に集計行を出す:

> **集計**: 成功 N 件 / スキップ M 件 / 失敗 K 件

## Technical Notes

- **`libmp3lame`**: ffmpeg 同梱の MP3 エンコーダ。Homebrew 版 ffmpeg にはデフォルトで含まれる
- **`-b:a 192k`**: CBR 192kbps。音楽でも効果音 (SE) でも十分な音質を確保しつつ、ファイルサイズも妥当
- **`-map_metadata 0`**: 入力の MP4 タグ（タイトル/アーティスト等）を MP3 ID3 タグに可能な限り引き継ぐ。動画ストリームを含まない純粋な m4a を想定
- **`-hide_banner -loglevel error`**: コンソール出力をエラーだけに絞り、ステップ表示が埋もれないようにする
- **出力先固定の理由**: 元ファイルと並べることで、変換前後の比較・差し替えが直感的になる。明示的に別の出力先を使いたい場合は、変換後にユーザーが手動で移動する想定
